## What's new in 0.7.0

- **Quick connect.** Press `o` or `ctrl+l` in the list, `ctrl+alt+n` in a session, use the button beside *New*, or run `omaremote quick`. Type an address (`pc.acme.lan`, `alex@server`, `vnc://10.0.0.5:5901`) and connect without saving it. The protocol follows what you type until you pick one. An address typed in the search field offers *Connect to …* on top of the list. Recent quick connections stay on this system only (never synced or exported); `s` saves one as an ordinary connection, `del` forgets it.
- **Omarchy's Super+V and Super+C work in sessions.** In an SSH tab, Super+V pastes and Super+C copies. In RDP, Super+V pastes as Ctrl+V. The connection's *Super key* setting now also holds in RDP tabs: when it is off, Super never reaches Windows.
- **Text fields never read the clipboard by themselves** ([marketplace review #11361](https://github.com/omacom/omarchy-plugin-marketplace/issues/11361)). Before, Qt's text field fetched the clipboard's contents every time the clipboard changed and every time a field got focus. Now the clipboard is only read when you paste (ctrl+v, shift+insert, Super+V, a middle click). A paste is at most 16 KiB, read within 2 seconds, and goes in as one line. There is no right-click menu on fields any more. OMARemote now depends on `wl-clipboard`, which Omarchy already installs.
- **Every field has a sensible maximum length.** For example, 253 characters for a host, 1024 for a user name and 4096 for extra options. A paste that does not fit is refused with a hint, instead of being cut short. Imported and synced files are held to the same limits, and a connection or group with a longer field is skipped, with the reason shown. The numbers and their sources are in `docs/limits.md`. Pasting into a remote session is not limited.
- **Fixed:** you can empty the port, width and height fields again. Before, they filled back up with the default, so 3389 could not be changed to 4389.

## Security review

Reviewed everything since 0.6.1 against `docs/security-review.md`. Three kinds of attacker were considered: a malicious server, a malicious sync or import file, and another account on the same machine.

- **Found and fixed:** on the quick connect card, a credential set filled in from a recent quick connection stayed selected after the address was changed to another host. Its password would then have gone to a server nobody chose that set for. Now the set is dropped as soon as the address changes to another host; a set you pick by hand stays. Covered by `tests/test_quick.py`, which fails without the fix.
- **Quick connections:**
  - A typed address goes through the same checks as a saved one when connecting (`check_host`: no leading `-`, no control characters).
  - A typed SSH user name reaches ssh only as the value of `-l`.
  - A credential set is never preselected for a typed address.
  - The sign-in prompt's password goes only to the session process and is never stored.
  - Quick connections are not in exports or sync files.
- **New processes:**
  - `terminal-tag` and `quick` pass only a process ID and fixed words, with nothing private on the command line.
  - The window tag uses only Hyprland's own window address.
  - `wl-paste` gets fixed options only.
- **Keys sent to sessions:** the view now adds Shift or Ctrl around a sent shortcut, and only lifts a Super that was passed on. It never adds Super. With the *Super key* setting off, the RDP process drops Super.
- **Untrusted data:** the new field limits also apply to import and sync, so an oversized value never reaches an editor. Nothing new is shown as rich text.
- **Dependencies:** `wl-clipboard` (Arch `extra`) is in the PKGBUILD, and `install.sh` checks for it.
- **Left as it is:** pasting into a remote session has no size limit, on purpose. It is how you paste a script into a session, and the session sees only what you paste.
