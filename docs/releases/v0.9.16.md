## What's new

- **Theme:** the windows no longer read Omarchy's theme files on the UI thread, so a theme file
  that is slow or never ends cannot freeze them. A window shows once its theme is in (at the latest
  after a second), so it never flashes the default colours first. A theme switch still applies
  live.
- **Own windows open without a flash.** Hyprland first opens a new window tiled; OMARemote now has
  everything ready before the window shows and floats, sizes and centres it in one step, with only
  the background visible until then (measured: 52–85 ms instead of up to 670 ms).
- **Super+C / Super+V in an SSH session in its own window** now copy and paste, as they do in a
  tab. The window never got Hyprland's terminal tag before.

## Security review

The Reviewer reviewed every change and ran the omarchy-plugin-security skill on it; nothing open.
This closes the last item of its second sweep (S5): theme files are read in the background, and
text longer than 64 K characters is not parsed. Tested with a theme file that is a FIFO, a link to
/dev/zero and 300 MB: the window shows with the default colours and quits cleanly. A size bound on
the read itself is not possible here, because Omarchy's Commons.Color reads the same files whole
in the same process; that bound belongs in Omarchy (an issue is drafted). Placement commands sent to Hyprland are built
from Hyprland's own window address and whole numbers only.
