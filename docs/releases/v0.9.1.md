## What's new in 0.9.1

A security release for sync. Everything from 0.9.0 (Gliff: another Omarchy machine's desktop in a tab) is unchanged.

- **A synced move into another group now asks first** when it would widen what the connection uses. Whoever can write your sync folder could add a new group that shares the home folder (or the microphone, or goes through another gateway or KDC) and move one of your connections into it: only the connection's group changed, so the confirmation you get for such changes was skipped, and the next session shared your home folder with that server. Such a move now waits in the same banner as a changed address, until you accept it. Reported by the Omarchy plugin marketplace's security review (omacom/omarchy-plugin-marketplace#11776). The gap is as old as these confirmations: 0.5.1 for gateways and KDCs, 0.8.2 for sharing.

## Security review

Reviewed everything since 0.9.0 against `docs/security-review.md`: the change to sync's merge. Synced connection changes are now compared as a session would use them (the group's settings, then the connection's own, against the groups as they were before that file), and a group that is new here is checked like an existing one when a connection here already names it. Each path has a test that fails without the fix: a move into a new group with home-drive, microphone, gateway or KDC; a move into a group that gained such a setting in the same file; a new group a connection here already names; and a move that widens nothing, which still just arrives.

Left as is: a new connection that arrives in a group with a credential set uses that set, as it always has; it is a connection you did not make, and nothing connects until you start it.
