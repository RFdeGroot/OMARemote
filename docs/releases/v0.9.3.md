## What's new in 0.9.3

A security release for sync, from a review of every way a synced file can change what this system signs in to or shares. Everything else is unchanged from 0.9.2.

- **A synced group change no longer slips past while a member is in Recently deleted.** If the only connection in a group that signs in here was in the trash, a new gateway, KDC or sharing setting for that group arrived without asking; restoring the connection afterwards then compared it against the group as it had become, so its saved password went to the new gateway without the confirmation. Members in the trash now count.
- **A synced group deletion asks first** when this system signs in through the group and the group held a gateway, a KDC or a security level (NLA or TLS). Its connections would otherwise sign in another way: directly instead of through the gateway, with a KDC found through DNS, or with the security level back on *auto*. *Keep mine* keeps the group and sends it back to your other systems.
- **Switching the clipboard back on now counts as sharing**, like the home folder and the microphone: a synced change that turns it on for a connection that signs in here waits in the same banner.
- **A new protocol without a port of its own counts as a new port.** Changing RDP to VNC moved the connection from port 3389 to 5900 without asking; the check now compares the port a session will use.
- **A file you import by hand no longer deletes groups.** An import only ever adds and updates; group deletions in the file were still applied.
- **A broken or hostile sync file can no longer stop sync.** A value of the wrong kind (a host that is a number, a date that is text, a file that is not an object) stopped every sync round until the file was removed; such entries are now skipped and named in the sync status. A change dated more than a day in the future is skipped too: it would win over every edit you make here.

## Security review

Reviewed everything since 0.9.2 against `docs/security-review.md`. After two sync findings in a row from the Omarchy plugin marketplace's review (omacom/omarchy-plugin-marketplace#11776, #11837), this release reviewed all of sync's merge rather than only the changes: every field a synced file carries (directly, through a group, or through a group's deletion), everything it can add, its tombstones and the trash, *Keep mine*, and manual import. Six holes were found and fixed, listed above; each has a test that fails on 0.9.2. Checked and unchanged: passwords are only read from the keyring when *Save password* is set on this system, and that setting never syncs, so a synced connection cannot borrow a saved password by taking another connection's id; credential sets, user names, keys, certificate checks and extra arguments never sync.

Left as is: a file you import by hand is taken as yours, so its address changes apply without the banner, as before. A view-only VNC connection switched to full control, or *grab keyboard* switched on, arrives without asking: both send only what you type into that session.
