## What's new in 0.8.2

A security release: sync asks before it shares, and SSH keys are guarded like passwords.

- **Sync asks before it shares.** When another system switches on *Share home folder* or the microphone for a connection or group that signs in here, the change waits in the same banner as a new address: *Accept* or *Keep mine*. Switching them off still arrives straight away.
- **An SSH key counts as signing in.** A synced change to the host of an SSH connection with a chosen key now waits for you too, so your key is never offered to a server you did not pick.

## Security review

Reviewed the paths by which data from sync and import files reaches a config file or a command line, against `docs/security-review.md`: FreeRDP's arguments, the VNC and SSH session settings, the ssh command line, `~/.ssh/omaremote.conf`, the Hyprland hotkey file, the private `krb5.conf`, the SFTP address and every command the interface starts. Found and fixed, each with a test:

- A synced connection or group could switch on home-folder or microphone sharing for a connection that signs in here without asking (import already refused this). It now waits for confirmation.
- A synced host change on an SSH connection with a chosen key went through without asking; the key would then be offered to, and written into `~/.ssh/omaremote.conf` for, the new host. It now waits for confirmation.
- `~/.ssh/omaremote.conf` checked a host only for spaces and `#`, so a host pattern such as `*` saved before 0.5.1 (sync and import refuse those since) would have given the key and user name to every server. Only plain host names are written now.
- The Kerberos realm named the cache and config files before it was checked; it must now be a plain name first (the domain is set on this system only, so this is hardening).

Left as is: a manually imported OMARemote export still takes new addresses without asking, because you picked that file yourself.
