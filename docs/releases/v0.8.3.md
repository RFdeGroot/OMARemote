## What's new in 0.8.3

- **Import from 1Remote.** Coming from Windows? Settings › Import & export › **From 1Remote…** reads 1Remote's database (`1Remote.db`, a `.db` file), and **Import…** takes it too. RDP, VNC and SSH servers come along with their port, user name and domain, RD Gateway, clipboard and sound settings, and 1Remote's first tag becomes the group. As with the other imports you see the list first, and nothing that is here already is added twice. Passwords stay behind, and so do drive sharing and the commands 1Remote runs around a connection.

Thanks to Christian Grasser (@chrisonline) for this contribution (#2), his second after the RD Gateway domain and password in 0.6.0.

## Security review

Reviewed everything since 0.8.2 against `docs/security-review.md`, with the 1Remote database treated as a file from someone else: how it is opened, what SQLite runs while reading it, and where each field goes (the same host, gateway, length and credential checks as `.rdp` and Remmina imports). Found and fixed, each with a test:

- A database whose `Servers` was a view instead of a table ran whatever query the file held while it was read (a recursive one kept the import busy). It must now be a table, nothing in the file's schema runs functions, and a read stops after five seconds.
- A list or a number where 1Remote writes a choice or its tags stopped the whole import with an error. Such fields are now ignored.
- The file was checked (an ordinary file, at most 64 MiB, a SQLite database), then opened again by name, so a file swapped in between was read unchecked. The checked contents are now read from memory, and SQLite never opens the file.

Left as is: a connection with *Microphone* on in 1Remote arrives with it on, as from `.rdp` and Remmina files. It is a new connection you pick from the list, and it signs in nowhere yet.
