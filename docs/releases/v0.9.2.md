## What's new in 0.9.2

A security release for sync. Everything from 0.9.0 (Gliff: another Omarchy machine's desktop in a tab) is unchanged.

- **A synced restore from Recently deleted now asks first** when it would point the connection elsewhere or share more. Whoever can write your sync folder could bring back one of your deleted connections with another host, gateway or KDC, or with your home folder or microphone shared; it kept this system's saved password, credential set or SSH key, so the next session sent them there, without the confirmation you get for such a change. A restore like that now waits in the same banner as a changed address. *Keep mine* leaves it deleted, and that deletion goes back to your other systems. Reported by the Omarchy plugin marketplace's security review (omacom/omarchy-plugin-marketplace#11837).
- **A new connection from another system no longer signs in with its group's credential set.** It arrives asking for a password when you connect, as imports already do; pick the group's set in its editor once to use it. Before, a sync file could add a connection to any host, under any name, in a group with a set, and the set's password went there when you opened it.
- **A move into a group whose credential set signs in now asks first too**, when it changes where the connection points. The check looked at the connection as it was here, which did not sign in when its own group had no set.

Also new: the README opens with a 30-second video of 0.9.

## Security review

Reviewed everything since 0.9.1 against `docs/security-review.md`: the changes to sync's merge and to *Keep mine*, and the README. Every synced path that ends in a connection here now goes through the same check: a change, a restore from the trash, and a new connection. Changes and restores are compared as a session would use them (group settings, then the connection's own), and signing in here is checked both before and after the change. New connections never take a credential set. Each path has a test that fails on 0.9.1: a restore with home drive, microphone, another host, gateway or KDC; a restore into a group with sharing; a new connection in a group with a set; a move into a group whose set signs in. Restores that widen nothing, or that sign in nowhere here, still just arrive.

Left as is: a file you import by hand (Settings › Import & export) is taken as yours, so its changes and restores apply without the banner, as before.
