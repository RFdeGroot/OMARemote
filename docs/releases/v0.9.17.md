## What's new

- **Faster sessions.** The session view now uploads only the parts of the picture that changed to the
  GPU, not the whole desktop on every update. Dragging a window over a Retina-sized desktop went from
  20% to 3% CPU in the view, and a blinking text caret from 30 MB to under 1 KB per update.
- **VNC Low is 16-bit colour.** *Low* quality asks the server for 16-bit colour on top of strong
  compression: a third less data from any server. It matters most for a Mac, whose Screen Sharing has
  no Tight or JPEG. Over a 100 Mbit link a Retina Mac went from 5 to 10 updates a second.
- **No more stale patches in RDP.** Dragging a window around fast could leave bits of the old picture
  on screen until something redrew them. Two threads wrote to the window at the same time and lines got
  lost; that cannot happen any more, and a large burst of changes ends with one full redraw.
- **Clipboard, Gliff:** nothing moves at connect. Each machine keeps its own clipboard until something
  is copied during the session, so a clipboard history on either side never picks up what the other
  held. A new per-connection switch, *Copied passwords*, also shares what a password manager copies (off
  by default, never synced, not set by groups).
- **Clipboard, RDP and VNC:** when the clipboard here is cleared (a password manager clearing a copied
  password, for example), or you copy something else while the session is not focused, the server loses
  what it was offered too. Switching Clipboard off mid-session does the same. A copy made on the server
  itself stays there. VNC now behaves like Gliff at connect.
- **Hotkey windows** hang from the top edge of the screen, like Omarchy's console, and are in place
  before they slide in.
- **RDP at 125% or 150%:** the picture starts on a whole screen pixel, so fonts no longer look
  pixelated in a tab of an odd width.
- **Measuring:** VNC and RDP sessions write a `stats:` line to their log for each busy second (updates,
  data, decoding time), to see where a slow session's time goes.

## Security review

The changes since 0.9.16 were reviewed against docs/security-review.md, and the Reviewer reviewed every
commit and ran the omarchy-plugin-security skill on them; nothing open. Checked in particular:

- *Copied passwords* is this computer's own: it is in `LOCAL_KEYS` and `GROUP_LOCAL_SETTINGS`, so no
  sync, import or group file can switch it on, and a connection with it on counts as signing in here, so
  a synced change of its address waits for you.
- Rectangles from a server or session are clipped to the picture before anything is uploaded; the
  view's `view-stats` line is checked to be digits before it is logged.
- The 16-bit picture buffer is sized from the same checked desktop size as the 32-bit one.
- The clipboard watch (`wl-paste --watch`) only reports that the clipboard changed, never reads its
  contents into OMARemote, and ends with the window that started it.
- The session link is now safe to write from two threads; a write that fails shuts the socket down and
  leaves closing it to the main thread.
