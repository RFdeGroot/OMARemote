## What's new in 0.9.6

A security release for copying files to a Gliff desktop, from the Omarchy plugin marketplace's review (omacom/omarchy-plugin-marketplace#11862). Everything else is unchanged from 0.9.5.

- **A pasted file is the one you copied.** When the remote machine pasted files you had copied, OMARemote opened each one again by its path at that moment, and only checked the last part of that path for a symlink. If someone else could change a folder you copied from (another account, in a shared folder), they could swap a folder in the middle of the path, or the copied folder itself, for a link to one of your private folders between your copy and the paste, and the remote would receive your files from there. OMARemote now opens what you copy once, when you copy it, and reads every file from there: through no symlink anywhere in the path, and only while it is still an ordinary file and the same file you copied. A file swapped for another one, a FIFO or a link is not sent; the paste of that file stops.
- **Never more than offered.** A copied file that grows after the copy is not sent past the size the remote was told.
- **A huge folder is refused sooner.** A folder whose file names together pass the limit for one copy (512 KiB) is refused as soon as the limit is reached, instead of after walking all of it.

## Security review

Reviewed everything since 0.9.5 against `docs/security-review.md`, with files we open after checking them as the focus. Fixed: the path check reported in #11862, and in the same class the copied root reopened by name and nothing checking that the file opened was the file offered. The checklist's lesson on this class now asks for the whole path to be checked and the file's identity after opening. Each has a test that fails on 0.9.5 (in `gliff-proto-test`: a folder in the path swapped for a symlink, a file swapped for a FIFO and for another file, the root swapped after the copy, and a tree past the path limit). Checked and unchanged: files pasted *from* the remote only go into a fresh private folder of ours, created without following links and never over an existing file; the RDP, VNC and SSH session processes open no copied or synced files by name later; RDP, VNC and SSH have no file clipboard of their own.
