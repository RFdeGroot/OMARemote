## What's new in 0.9.10

- **Updates download within limits.** The Update button downloads the new package and its signature first, then checks the signature. Until now, those downloads had no size or time limit: a server pretending to be GitHub could keep sending data until your disk was full, before the check ever ran. Each download now has a size cap (64 MiB for the package, which is about 0.5 MB today, and 64 KiB for the signature) and a time limit, and it only goes over HTTPS, redirects included. The same goes for the releases list that OMARemote reads to see whether there is an update for itself or for the bar plugin (4 MiB, one minute).

## Thanks

The marketplace reviewer (HANCORE-linux) found this in the bar plugin's install button, in [#12133](https://github.com/omacom/omarchy-plugin-marketplace/issues/12133). OMARemote's own updater had the same gap.

## Security review

Reviewed everything since 0.9.9 against `docs/security-review.md`. The only change is this fix.

- **Downloaded before it is checked, now bounded.** `omaremote-update`: `curl --max-filesize` (which also stops a stream that announces no length, at the cap), `--max-time`, `--connect-timeout`, `--proto` and `--proto-redir '=https'` on the package and the signature. `omaremote-session`: the update check and the plugin check read the releases list through one function that reads at most 4 MiB within 60 s in all (a socket timeout alone counts per read, so a slow trickle never tripped it) and refuses a redirect away from HTTPS.
- **The whole class checked.** Every other place that reads data from outside already had a byte cap and a deadline: sync and import files, the clipboard, session messages, Gliff. The release workflow's Arch Linux ARM image, also downloaded before its signature is checked, now has a cap and a deadline too.
- New tests: every download carries its cap and deadline, a failed download installs nothing, and a list past the cap, a trickle past the deadline and a redirect to plain HTTP are all refused. They fail without the fix.
- The plugin uses the same limits; they are now part of `docs/plugin-interface.md`.
