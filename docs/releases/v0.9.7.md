## What's new in 0.9.7

A security and reliability release from a full code review of 0.9.6. Nothing you set up changes; the one thing you may notice is that a remote session's clipboard now waits until you are back in its tab.

- **A broken connections.json is never overwritten.** If the file no longer read as valid JSON (a hand edit with a trailing comma, half a file), the next change in the window, even pinning the list, replaced it with an empty one: every connection, group and the trash gone. Now nothing is written until the file reads again, a copy is kept beside it as `connections.json.broken`, and the status bar says so. When each connection was last used moves to a file of its own (`last-connected.json`), so the window is the only one writing `connections.json`.
- **Sync folder: no planted files.** Whoever can write to your sync folder (another account, a shared Nextcloud or Syncthing folder) could plant a link where OMARemote wrote its temporary file and have the next sync overwrite any file of yours; a FIFO stopped sync until a restart; a huge file or a link to `/dev/zero` used up memory. The temporary file now gets a new random name every time, and other systems' files are read only when they are ordinary files of at most 16 MiB (no links in the sync folder). A sync round that takes longer than a minute is stopped.
- **Sessions no longer vanish under load.** The session process and a session's own window both rewrote the session's record at once: it could come out corrupt (the session disappeared from the window and the bar) or go back to "connecting". They now take turns.
- **A server cannot claim a giant desktop.** A desktop size from the server larger than 8192 pixels a side is refused instead of taking the window, and every tab in it, down: RDP and VNC end the session and say why, Gliff shows nothing of it. The window also checks the shared picture before it maps it.
- **The clipboard waits for you.** Text a remote session copies (RDP, VNC, SSH) arrives in your clipboard once its tab has the keyboard, not while you work elsewhere, and is dropped if you copied something yourself in the meantime (as Gliff already did). SSH connections now have the Clipboard switch: off, programs on the server (tmux, Neovim) can no longer set your clipboard; copying a selection still works.
- **Updates only go forward.** The updater would install an older release when that was listed as the newest; it now installs only a newer one, and only with a signature from OMARemote's own release key.
- **Smaller fixes.** Gliff connections without a port of their own showed `:3389` in the list. `omaremote open`, `quick`, `adopt` and `restart` ended silently when Hyprland could not be asked for the window. A connections.json of an unexpected shape no longer crashes the bar's list. The `~/.ssh/config` line is found again after an editor added a trailing space or Windows line endings. Hotkey windows work with a home folder such as `/home/josé`. An SSH server can no longer grow the window title without limit. A clipboard owner that never finishes no longer holds back a Gliff file offer. The README's manual install now checks the package's signature.

## Security review

A full review of 0.9.6 by a second session, then a re-review of every fix against `docs/security-review.md`. Fixed: everything above. Each fix has a test that fails on 0.9.6 (the real `Store.qml` against a broken file; a FIFO, a link to `/dev/zero`, a huge file and a planted link in the sync folder; two processes rewriting one session record; a fake VNC server claiming 65535×65535; frames shorter than they claim; the clipboard while the tab is away; a downgrade and a signature by another key; and the smaller ones). Checked and unchanged: sync's merge rules (the 0.9.3 audit), every place a host, id or line reaches a config or command line, secrets (stdin and the keyring only), notifications, the clipboard read limits, cursor limits, Gliff's frame limits and file clipboard, the import parsers, Kerberos. Also checked: systemd 262 expanding `${…}` in commands started through `uwsm-app` (it broke the bar plugin's install button) cannot be triggered from anything a connection holds; a test keeps it that way. New lessons in `docs/security-review.md`: never a fixed name in a folder others write, a server acts on the desktop only while its tab has the keyboard, text on a systemd unit's command line, updates only forward. The release workflow's GitHub Actions are pinned by commit.
