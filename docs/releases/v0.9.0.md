## What's new in 0.9.0

- **Gliff: another Omarchy machine's desktop in a tab.** Pick **Gliff** as a connection's protocol and OMARemote shows that machine's Hyprland desktop, streamed over ssh by [Gliff](https://github.com/omacom/gliff). OMARemote speaks Gliff's protocol itself, so there is nothing to install on this machine; the computer you connect to needs Gliff (`omarchy pkg add gliff`; it is set to come preinstalled with Omarchy 4.5).
  - **Mirror** a remote screen, or give the tab a **private screen** of its own on the remote that follows the tab's size and scale.
  - **Sharp 4:4:4 text** with VA-API, pictures straight from the decoder to the screen on the GPU; *Low bandwidth* and *Full 4:4:4* when you want to choose.
  - **Your keys go along**, your keyboard layout included. While the pointer is on the picture the tab takes Hyprland's shortcuts, `super` included; moving off, `ctrl+alt+esc` or `shift+esc` gives them back.
  - **Clipboard both ways**: text, images and files, nothing sent until you paste, shared only while the tab has the keyboard, never a password manager's selection.
  - **Reconnects** by itself after a dropped link.
  - **The link's health in the bottom bar**: a green, orange or red dot with as many facts as fit (fps, round trip, bandwidth, decoding); click it for all of them.
- **New screenshots** in the README, Gliff included.

**Known issue:** a monitor tool on the remote machine, such as the hyprmoncfg plugin, can change a *Private screen* right after it appears, and the picture stops. Gliff's own client has the same problem. Use *Mirror*, or stop the tool while you connect; see the README's Gliff section.

## Security review

Reviewed everything since 0.8.3 against `docs/security-review.md`, with three new sources of data in mind: what a Gliff server sends (its messages, video, cursor and clipboard, files included), the words that reach the remote shell, and the pictures the session hands the window. The remote command is fixed words and checked names only; the protocol reader checks every length and type and caps every list; clipboard files from the server go only into a fresh private folder, by relative paths without `..`, never over an existing file. Found and fixed, each with a test:

- **gliff-server's path travelled with sync and import.** Whoever could write the sync folder could choose the program ssh runs on the remote machine. It now stays on this system, like *Extra ssh options*.
- **A server's error message could add lines to the session log**, which OMARemote reads line by line (a forged "connected" or "connection failed"). Every log line is now one line, for every session type.
- **A file inside a copied folder** was opened by name when the remote pasted it; replaced by a symlink in between (in a folder another account can write), it would have handed over the file it points to. Symlinks inside copied folders are no longer followed.

Also hardened: damage rectangles from the server are computed in 64 bits before they are clipped to the picture.

Left as is: a Gliff session runs `ssh` with the host on its command line, as SSH sessions do (documented in the README). The plugin now uses Qt's private GUI headers (for the EGL import); they are part of qt6-base.
